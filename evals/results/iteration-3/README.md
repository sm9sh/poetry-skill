## Що знайшов раунд

| Проблема | Де | Виправлення |
|---|---|---|
| «Тексту немає» прочитано як «пісня без слів»: замість лірики — вокаліз `(о-о-о)` | eval 6, зі скілом (baseline помиляється так само) | Пісенний скіл, крок 1: «тексту немає» означає, що текст треба написати. Безсловесний трек — лише якщо про це сказано прямо. Перевірено на трьох запусках: у всіх трьох є текст |
| Наголос «нОвий» замість «новИй» у готовій пісні, хоча `check_lyrics.py` попередив | повторний запуск eval 6 | Неправильний наголос на слові зі списків скрипта — тепер ERROR, а не WARNING. Скіл каже виправити всі ERROR. Розбіжність зі словником лишається WARNING, бо словник може не знати засвідченого поетичного варіанта |
| Суддя сам рахує склади й помиляється | eval 4, ітерації 2–3 | `check` рахує склади програмно, суддя отримує їх як факти |
| JSON судді з сирим переносом рядка ламав парсер | eval 8 | `json.loads(..., strict=False)` + тест |
| Поетичний скіл пише користувачу, що не запускав сканер | eval 2 | Правило «тільки вірш»: не писати про скрипти, навіть у списку змін |

- Поетичні запуски досі не користуються інструментами (1 хід, без `scan_meter.py`). Склади при цьому правильні, тож поки що це не проблема.
- Коломийка (6.75) і пісня для Lyria (5.75) — найслабші місця. Наступну ітерацію варто почати з них.
- Пісні треба послухати в Suno v6-mini / Lyria 3.5: наголоси й проспівані вказівки видно лише на слух.
